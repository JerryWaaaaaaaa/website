### Code changes
- `HeroV6.tsx`: the `<img class="v6-hero-bg">` is replaced by `<HalftoneImage … interactive />`.
  - `src="/v6/hero/source.webp"` is the photo the shader samples.
  - `fallbackSrc="/v6/hero/bg.webp"` is the baked render.
  - `HERO_HALFTONE` and `HERO_PLACEMENT` are module-level constants.
- `HalftoneImage.tsx`: `ImagePlacement` gains an optional `scaleDots?: boolean`.
  - When true, `dotSize` is read as frame px. Dot size, blur radius, cursor radius and the dirty-rect padding all multiply by `dotK()`.
  - `dotK() = max(max(canvasW / frameW, canvasH / frameH), MIN_DOT / dotSize)`, with `MIN_DOT = 3` CSS px.
  - When false or absent, `dotK()` returns 1, so the CTA is unchanged.

### Integration notes for Curry
- No new dependencies. The shader is raw WebGL2 and needs no library. Keep `bg.webp` in production, because it is the fallback for no-WebGL2, touch and reduced-motion cases.
- The effect depends on the `HalftoneImage` setup effect re-running only when `src` or `interactive` change. `params` and `placement` must stay static (module-level constants). Inline objects would not re-trigger setup, so edits to them won't apply.
- The hero and CTA now use both live-shader slots. Don't add a third shader on this page without cutting one, as the DESIGN.md budget says.
- Prototype-only: the constants (`dotSize`, the 3px floor, `POINTER_RADIUS` 180, `POINTER_BOOST` 0.6) were tuned by eye against Figma. Nobody has checked mobile performance or the 3px floor on real phones. Ask Jerry before changing them.
